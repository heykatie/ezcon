# ezcon demo video plan

Target: 3–5 minutes, ideally about 4:20. Judging emphasizes the problem statement and demonstration. Spend about 30 seconds stating the problem, then show the solution and how the sponsor tools contribute. Keep the story on one attendee goal; avoid a feature tour.

## Storyboard

| Time | Show | Explain |
| --- | --- | --- |
| 0:00–0:30 | Title and Today screen | “At a conference, the job board, agenda, people and travel costs are disconnected. I can’t quickly tell which real opportunity connects me to someone worth meeting, whether I can afford to get there, or what to do afterward. ezcon turns that research into one practical plan.” |
| 0:30–1:05 | Explore → Hiring connections: a verified open role, employer application link and linked conference session/person | Explain that the role was checked against the employer source and that a conference connection exists. Keep the fit caveat visible; this is not a referral or guaranteed interview. |
| 1:05–1:40 | Why this fits → show the returned FalkorDB path in ezcon | Explain the actual relationship chain, e.g. profile interest → session → speaker → company → open role. The highlighted edges must be returned by the graph query, not generated by the model. |
| 1:40–2:20 | Add session to Schedule; show Get ready and commute/parking options; open the full-day Schedule | Show the deterministic time and cost comparison and one relevant preparation action. State that estimates depend on event time and source freshness. Never imply prices or availability are guaranteed. |
| 2:20–2:55 | Run one bounded live research call; show the TrueForge tool trace and Bright Data source result | Attribute clearly: TrueForge/OpenAI ran the bounded agent call; Bright Data fetched the approved source page; ezcon’s parser extracted the fields and checked them. Point to the URL, retrieved time, and extracted title/speaker/time/venue. The latest verified run used one `scrape_as_html` call and returned the WAD session record. |
| 2:55–3:35 | Record a fictional meeting, reload/reconnect, show the saved relationship and a follow-up draft | Explain that FalkorDB stores the profile-scoped relationship and that a later query can change based on it. Label the person and interaction as fictional demo data. Follow-up is a draft; ezcon does not send it. |
| 3:35–4:05 | Show Qodo’s review finding, resulting fix and regression test in the follow-up PR (once completed) | Name one concrete finding and show the change plus passing test. A Qodo installation or generated summary alone is not evidence of a completed review. |
| 4:05–4:20 | Briefly show Explore → Side quests on historical WAD, then close on Today | Explain that the AirPods raffle is a historical replay: the listing names the winner time and booth, but entry/presence rules are unknown. The sample ticket is fictional. End with the useful outcome: a sourced opportunity, feasible plan and remembered next action. |

If recording closer to three minutes, omit the side-quest replay and shorten the commute explanation. Keep the 30-second problem, the graph path, a real tool trace and the remembered meeting. If going longer, use time to show source provenance or one honest failure/unknown-data case, not more features.

## Before recording

- Confirm the app is running and the exact build being recorded is the one intended for judges.
- Check the current role source and session source; use a role only if its employer link still opens and its status is still current.
- Use only the approved sponsor credits. Do not run a call whose billing source is unclear.
- Reset the fictional demo profile and clock as needed. Keep secrets, personal tabs, real notes, attendee data and real ticket photos out of the capture.
- Prepare the exact Qodo review, finding, fix and passing regression test; only show the follow-up PR once Qodo has completed its review.
- If showing the authenticated WAD goodies/raffle listing, show only the historical listing already approved for public display. Do not show the attendee directory or personal ticket information.
- Capture desktop/browser content only, and keep the app at a readable zoom. Make sure important labels are not hidden by a cursor or overlays.

## Sponsor-tool evidence to show

- **FalkorDB:** graph is central to the recommendation and meeting memory; show the actual returned multi-hop path and a later query that reflects the saved fictional meeting.
- **Bright Data:** show the real bounded fetch, source URL and retrieved content. Do not say it scraped the authenticated WAD goodies page; that listing was manually inspected in the user’s logged-in browser.
- **TrueForge + OpenAI:** show the actual model/tool trace, bounded tool permission and parsed result. Do not present model text as authoritative event or job facts.
- **Qodo:** show a completed review on the follow-up PR, one actionable finding, code fix and regression test. Clearly distinguish a finding from a passing test.

## After recording

Upload an unlisted YouTube video or a link-viewable Drive video. Open the link in a signed-out/private browser session and verify playback. Submit the video URL and the live demo URL through the organizer’s verified submission portal. The official event page showed a 5:30 PM judging time; the submission destination must be verified before sending the links.
